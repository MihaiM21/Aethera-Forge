# Aethera — conventions for workers

Aethera is a self-hosted deployment platform (Coolify alternative). Read `docs/plan.md` (approved plan), `docs/roadmap.md` (status) and relevant `docs/architecture/*.md` ADRs before starting. Product spec: `docs/idea/01_AppIdea.md`.

## Layout
```
src/control-plane/   .NET 10 solution Aethera.slnx: src/{Aethera.Api,Domain,Infrastructure,Engine,Agent.Protocol}, tests/{Aethera.Api.Tests,Domain.Tests,Agent.Protocol.Tests}
src/agent/           Go module github.com/mihaim21/aethera-forge/agent (cmd/aethera-agent, internal/*, gen/ = generated proto code)
src/web/             Next.js (App Router, static export, Tailwind v4, shadcn/ui), pnpm
proto/               Agent protocol (buf). buf.yaml / buf.gen.yaml at repo root
deploy/              docker-compose.dev.yml (Postgres 17, Redis 7)
scripts/             session-start.sh (Claude Code cloud bootstrap)
```
Dependency direction (.NET): Api -> Infrastructure, Engine -> Domain. Domain depends on nothing. NuGet versions live only in `Directory.Packages.props`; shared settings (net10.0, nullable, warnings as errors) in `Directory.Build.props`.

## Build and test
.NET (SDK 10 lives in `$HOME/.dotnet`):
```bash
export DOTNET_ROOT=$HOME/.dotnet PATH=$HOME/.dotnet:$HOME/go/bin:$PATH DOTNET_CLI_TELEMETRY_OPTOUT=1
cd src/control-plane && dotnet build -warnaserror && dotnet test
```
Database and Redis tests: about 470 of the .NET tests need PostgreSQL (some also Redis) and are **skipped silently** when these are not set, so a green `dotnet test` without them proves much less. CI sets them (service containers). Point them at a Postgres server whose role may `CREATE DATABASE` (each test class migrates and drops its own throw-away database) and, optionally, a Redis:
```bash
export AETHERA_TEST_DB="Host=127.0.0.1;Port=5451;Username=aethera;Password=x;Database=postgres"
export AETHERA_TEST_REDIS=127.0.0.1:6451
```
Start your own throw-away instances (cloud sessions have the PostgreSQL 16 binaries and `redis-server`). **Use a distinct port pair per parallel worker** (say 5451/6451 for one, 5452/6452 for the next) and **data dirs under `/tmp/<unique-name>`, never the shared scratchpad**: WP1.2 once clobbered WP1.3's database through a shared script.
```bash
PGBIN=/usr/lib/postgresql/16/bin; D=/tmp/aethera-wpX-pg; PGPORT=5451    # PostgreSQL refuses to run as root: use the postgres user
rm -rf $D && mkdir -p $D && chown postgres:postgres $D
su postgres -s /bin/bash -c "cd /tmp && $PGBIN/initdb -D $D/data -U aethera --auth=trust >/dev/null \
  && $PGBIN/pg_ctl -D $D/data -l $D/log -w -o '-p $PGPORT -c listen_addresses=127.0.0.1 -c unix_socket_directories=$D -c fsync=off' start"
mkdir -p /tmp/aethera-wpX-redis && redis-server --port 6451 --bind 127.0.0.1 --dir /tmp/aethera-wpX-redis --save "" --daemonize yes
# ... run the tests, then stop both:
su postgres -s /bin/bash -c "cd /tmp && $PGBIN/pg_ctl -D $D/data -m immediate stop"; redis-cli -p 6451 shutdown nosave; rm -rf $D /tmp/aethera-wpX-redis
```
`bash deploy/smoke.sh` runs the whole Phase 1 stack end to end (web export, API, throw-away Postgres/Redis, curl, headless Chromium) and takes the same `AETHERA_DB` / `AETHERA_REDIS` if you want it to use yours. The API serves the web export from `Aethera:Web:Root` (default `wwwroot`; in Development `src/web/out`); restart it after a new `pnpm build`.

Agent:
```bash
cd src/agent && go vet ./... && go test ./... && make cross   # static linux/amd64 + arm64 in dist/
```
Web:
```bash
cd src/web && pnpm install && pnpm lint && pnpm test && pnpm build   # build emits static site to out/
```
Proto (only when told to change it): `export PATH=$HOME/go/bin:$PATH; buf lint && buf generate`. Go code is generated into `src/agent/gen` and committed (the CI `proto` job fails if it is stale); C# is generated by Grpc.Tools at build time in `Aethera.Agent.Protocol` (namespace `Aethera.Agent.V1`), not committed.

Cloud sessions run `scripts/session-start.sh` automatically (installs .NET 10, buf, protoc plugins, restores deps). Egress is policy-restricted: some hosts (e.g. builds.dotnet.microsoft.com, ui.shadcn.com) are blocked; NuGet, npm, Go proxy and the Ubuntu archive work.

## Rules
- **Contracts**: `proto/`, DB migrations and OpenAPI conventions are owned by the orchestrator. Do not change them without being told to.
- Stay inside the paths your work package owns; parallel workers must not overlap.
- **Commits**: Conventional Commits (`feat(api): ...`, `fix(agent): ...`, `chore:`, `docs:`, `test:`). Small logical commits. Do not push unless instructed.
- **No secrets in logs**, errors or test output. Secrets are encrypted at rest, masked in the UI, redacted from logs.
- **Tests are required** for new code (xUnit, `go test`); keep builds warning-free.
- The agent executes only typed, allowlisted commands; never add arbitrary shell execution.
- API first: the UI must not contain logic the API lacks.
- **UI** must follow the "Design system" section of `docs/plan.md` (dark default, lime accent `#b8f26b`, mono labels, square corners, 1px borders, dotted-grid canvas).
